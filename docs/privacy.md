# 隐私与数据处理说明

- **适用版本**：vsc-postman `2.0` 及以后（VS Code 扩展、Edge / Chrome 扩展、Web 版共用同一份实现）
- **适用范围**：VS Code 扩展、Edge / Chrome 扩展、Web 版
- **最后更新**：2026-11-12

一句话结论：**vsc-postman 没有账号体系，不上传、不同步、不统计你的任何数据；集合、历史与设置只保存在你本机。**

## 1. 我们不收集什么

| 数据种类                     | 是否收集 | 说明                                                       |
| ---------------------------- | -------- | ---------------------------------------------------------- |
| 身份信息（姓名、邮箱、头像） | 否       | 没有注册、登录或第三方登录入口                             |
| 账号凭据                     | 否       | 无账号系统，因此也不存在密码或 Token 托管                  |
| 使用行为 / 埋点事件          | 否       | 代码中不含任何 analytics、crash reporting 或远程配置 SDK   |
| 设备指纹、崩溃日志           | 否       | 无此类上报端点                                             |
| 你的请求与响应内容           | 否       | 只存在于本机内存与本地存储，不会发往本项目作者或任何第三方 |

约束方式：扩展页面 CSP 为 `script-src 'self'`，扩展包内不得加载远程脚本；网络请求的代码路径只有「用户点击发送时对目标 URL 的请求」与可选的用户自建代理。

## 2. 数据存在哪里

| 运行环境                 | 存储介质                                      | 键                                                          |
| ------------------------ | --------------------------------------------- | ----------------------------------------------------------- |
| Web / Edge / Chrome 扩展 | 浏览器 `localStorage`                         | `vsc-postman:state`、`vsc-postman:app`、`vsc-postman:theme` |
| VS Code 扩展             | 扩展的 `globalState`（本机 VS Code 扩展存储） | `vsc-postman:state`、`vsc-postman:app`                      |
| 无持久化能力的环境       | 内存（关闭即消失）                            | —                                                           |

存储内容：集合与其中的请求（方法、URL、Query、Headers、请求体、`form-data` 字段）、历史记录（默认最近 50 条，可在设置页调整上限）、设置项（语言、主题、历史条数）。

`globalState` 是 VS Code 扩展的**本机**存储，不会随 Settings Sync 同步到其他设备；浏览器 `localStorage` 同理。

## 3. 数据生命周期

- **写入时机**：保存请求、发送请求产生历史、修改设置时写入。
- **保存期限**：你主动删除或清空前一直保留；历史按配置的上限自动裁剪最旧记录。
- **删除方式**：
  - 应用内删除单个请求、集合或历史；
  - Web / 扩展：清除该站点的浏览器数据；
  - VS Code：卸载扩展并清理其扩展数据，或在 VS Code 中清除该扩展的存储。
- **迁移**：当前提供「导出存储为 JSON」（Web 的设置页 / VS Code 命令 `vsc-postman.exportStorage`），**不提供导入**，因此换设备需要自行保留导出文件。

## 4. 网络行为

| 场景                       | 出站目标                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------ |
| 发送请求（扩展 / VS Code） | 你在 URL 栏填写的那个地址，直接由浏览器扩展的 Service Worker 或 VS Code 扩展宿主发出 |
| 发送请求（Web 开发环境）   | 先到本机 Vite 开发服务器 `/__http-proxy`，再由它转发到目标地址                       |
| 发送请求（生产 Web）       | 默认浏览器直连；**仅当部署方配置了 `VITE_HTTP_PROXY_URL`** 时经该转发地址            |
| 其他后台通信               | 无。不检查更新、不拉取远程配置、不加载远程代码                                       |

- 请求固定 `credentials: 'omit'`：不读取、不保存、不回传浏览器 Cookie；扩展不申请 `cookies` 权限。
- 响应与请求体只在内存中处理；`form-data` 的文件内容不被写入存储，只记录名称、大小、类型等元信息。
- 若你或你的部署方配置了自建代理，该代理的日志与留存策略由代理所有者决定，不属于本扩展的控制范围。

## 5. 权限用途

**Edge / Chrome 扩展**

| 权限                                        | 用途                                                                    | 必要性                       |
| ------------------------------------------- | ----------------------------------------------------------------------- | ---------------------------- |
| `host_permissions: http://*/*, https://*/*` | 调试对象是任意 HTTP 接口，域名无法预先枚举，因此需要全站访问能力        | 核心功能，缺少则无法发送请求 |
| 未申请 `cookies`                            | 不需要，也不读取登录态                                                  | —                            |
| 未申请 `tabs` / `storage` / `webRequest`    | 打开页面用 `chrome.tabs.create` 无需 `tabs` 权限；数据存 `localStorage` | —                            |

**VS Code 扩展**

| 能力                           | 用途                              |
| ------------------------------ | --------------------------------- |
| Webview（侧边栏 + 编辑器标签） | 承载 UI                           |
| `globalState`                  | 保存集合、历史与设置              |
| 文件选择对话框                 | 选择 `form-data` 要上传的本地文件 |
| 网络访问                       | 由扩展宿主发出你发起的 HTTP 请求  |

扩展不在后台扫描文件、不读取工作区源码、不在你未操作时发起网络请求。

## 6. 第三方

- **不集成**任何第三方分析、广告、崩溃收集或 AI 服务。
- 依赖库（React、Vite 等）随包分发，不在运行时与第三方服务器通信。
- 分发平台（VS Code Marketplace / Microsoft Edge Add-ons）会按各自的隐私政策统计安装量与评分，这属于平台行为，不由本扩展控制。

## 7. 安全提示

- 集合与历史中的 Headers 可能包含 Token，目前为**明文存储**，请勿在共享设备上保存生产凭据。
- 开发代理可在本机访问任意 URL，不要把开启该插件的 dev server 暴露到公网。
- 扩展的请求会携带 `Origin: chrome-extension://<id>`，部分服务端会据此限制访问，这属于目标服务的策略。

## 8. 变更

本说明随版本更新。若未来引入任何形式的数据上传（例如可选的云同步），会先在应用内明确提示并征得同意，再更新本文档与商店的隐私声明。
